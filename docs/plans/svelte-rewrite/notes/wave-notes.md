### Table Storage projection (B1-S1-T2)
- Contrary to the plan text, a `$select` projection against Azure Table Storage / Azurite does **not** return `PartitionKey`/`RowKey` unless they are in the select list (proved by a failing test). `ITableClient.QueryAsync(tableName, filter, select, maxRows, ct)` therefore always unions `PartitionKey` and `RowKey` into the select list, so callers may pass `select = ["Name","RuntimeStatus","CreatedTime","LastUpdatedTime","CompletedTime"]` and still read `row.PartitionKey` as the instance id. Non-selected columns (Input, Output, CustomStatus) are still absent.
- `maxPerPage` is `Math.Min(1000, maxRows + 1)`; `maxRows < 1` throws `ArgumentOutOfRangeException`. The result carries `(rows, truncated)`; B1-S2 maps those to `scanned`/`partial`.
- Nothing calls `QueryAsync` yet; the first caller is B1-S2-T2 (`AzureStorageAggregations.GetStatsAsync`).

### B1-S2-T1 — Added the pure StatsAggregator (plus InstanceRowLite) that turns a bounded Instances scan into contracts section 6 StatsResult, with 31 unit tests including a hand-computed 40 row fixture.

Deviations and facts later tasks need.

1. NAMING: the plan writes the input row as `InstanceRowLite { PartitionKey (instanceId), ... }`. I named the property `InstanceId` (documented as "in Azure Table Storage this is the Instances row's PartitionKey"), because the MSSQL implementation (B1-S2-T4) has an `InstanceID` column and no partition key. B1-S2-T2 must therefore write `new InstanceRowLite { InstanceId = row.PartitionKey, ... }`. Per wave-notes, `ITableClient.QueryAsync` always unions PartitionKey/RowKey into the select list, so `row.PartitionKey` is available even with the projection.

2. VISIBILITY: the plan calls InstanceRowLite "internal"; I made both it and `StatsAggregator` public, because the MSSQL package is a separate assembly and B1-S2-T4 must construct rows and call `Aggregate`. There is no InternalsVisibleTo in the repo.

3. SIGNATURE for B1-S2-T2 / B1-S2-T4: `StatsResult StatsAggregator.Aggregate(IEnumerable<InstanceRowLite> rows, StatsQuery query, DateTimeOffset now, bool truncated, int cap)`. `rows` null is treated as empty; `query` null throws ArgumentNullException. Callers pass `DateTimeOffset.UtcNow` for `now` and the settings cap for `cap` (the aggregator uses the `cap` argument, not `query.Cap`).

4. FIELDS THE AGGREGATOR DOES NOT FILL: `ElapsedMs` stays 0 and `Cached` stays false - B1-S2-T3 must set both (and may overwrite `GeneratedAt`, which the aggregator defaults to the supplied `now`).

5. SEMANTIC DECISIONS the plan left open, all pinned by tests, so MSSQL must match them:
   - `totals.all` counts orchestration rows only; entity rows count into `totals.entities` and `entitiesByName` and nowhere else (not in `all`, bins, byName, stuck, pending or suspended). `scanned` does include entity rows - it is how many rows the provider read.
   - Statuses nobody is in are absent from `totals` / bin `counts`, not present as 0. `all` and `entities` are always present.
   - A RuntimeStatus is canonicalised case-insensitively to its contract spelling; an unrecognised value is kept verbatim (trimmed) and a null/blank one becomes the key `Unknown` (new public const `StatsAggregator.UnknownStatus`). Unknown statuses count into `all` and `started` but into none of completed/failed/running.
   - Bin i is [start, end); the last bin also includes `to`. Rows outside [from, to] are ignored by the bins but still counted everywhere else. Bin edges are built with decimal tick arithmetic because 92 days x 366 bins overflows a long in the naive formula.
   - `sampleIds` are the 10 oldest of the set (by LastUpdatedTime for stuck/suspended, CreatedTime for pending), tie-broken by instance id; the thresholds are strict `<` (a row exactly at now - stuckAfterMinutes is not stuck).
   - Terminal rows without a CompletedTime contribute no duration, so a name can have failures but null p50/p95.
   - `byName` is sorted by started desc then name ordinal asc; `entitiesByName` by count desc then name ordinal asc.
   - Percentile rank is integer `(count * percent + 99) / 100`, not `ceil(count * 0.95)` in double (20 values at p95 must give the 19th value).
   - The entity name comes from the `@name@` part of the instance id via `ExpandedOrchestrationStatus.EntityIdRegex`, never from the row's Name column.

6. Nothing for the UI epic to work around: every StatsResponse field is filled from real row data; none is stubbed or nulled for lack of backend support.
